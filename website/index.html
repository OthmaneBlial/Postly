03 / A SMALL, REAL FIRST PROJECT

Hello, local.
Goodbye, setup maze.

The built-in Orders example creates a workspace and starts a loopback API. Send a request, change paid to pending, and see the response change.

No account, API key or external service. Native assertions need no Node.js.

Walk through the example ↗
THE SAME WORKSPACE, IN YOUR TERMINAL
postly demo ./orders-demo --port 3979

Leave the server running. In another terminal:

postly run ./orders-demo
EXPECTED STARTER RESULT2 requests. 5 assertions.

Both requests pass against the built-in API.
Change the checks; run them again.

Requires the current preview binaries or a source build.
The old v0.1.0 release does not include this example.

04 / CAPABLE, WITH CLEAR BOUNDARIES

Local by design.
Honest by default.

Files you can review.

One request per TOML file. Collections belong beside your code. Local environment values and runtime state stay out of ordinary commits.

More than REST.

HTTP, GraphQL, SSE, WebSocket and gRPC workflows share the Rust core. Read each protocol's guide for its supported behavior.

No compatibility theatre.

Postman migration has documented limits. Scripts are opt-in and require Node.js. Unsupported or ambiguous fields produce diagnostics.

Read the compatibility evidence ↗

Your data stays yours.

No Postly account or hosted workspace required. Remote requests still contact the endpoints you choose; local-first doesn't make a remote API offline.
